# KI-Tutor Questionnaire — Results Export

Self-contained export of the questionnaire results for statistical analysis.

- **Export date:** 2026-06-28
- **Responses:** 318 total — **34 teachers**, **284 students**.
  (The DB held 336 user accounts; 18 signed in but never submitted answers and are not included.)
- **Language:** All question texts and answer values are in **German**.
- **Privacy:** Pseudonymized. Respondent names and Azure AD object IDs were **removed**.
  Each respondent has a surrogate `respondent_id` (`T###` = teacher, `S###` = student).
  Student `class_name` is retained (useful for grouping); teachers have no class.

## The survey

There are two separate questionnaires, chosen by the respondent's role:

| Role     | Question-ID prefix | Count of questions |
|----------|--------------------|--------------------|
| Student  | `S` (e.g. `S0.1`)  | 39                 |
| Teacher  | `L` (e.g. `L0.1`, *L = Lehrer*) | 37    |

Each questionnaire is organized into 8 thematic **clusters** (0–7). The cluster grouping
is descriptive only — in the stored data every answer is a flat `questionId → value` pair.

## Files

| File | Contents |
|------|----------|
| `questions.json` | **Codebook / metadata.** Full definition of every question: text, type, answer options, Likert scale labels, cluster, and an `optional` flag. Includes a flat `questions_by_id` lookup. |
| `responses.json` | **All 318 responses**, each with `respondent_id`, `role`, `class_name`, `submitted_at`, `last_sign_in`, and the verbatim `answers` object. This is the lossless primary source. |
| `responses_students.csv` | Wide table, one row per student (284), one column per question. |
| `responses_teachers.csv` | Wide table, one row per teacher (34), one column per question. |

## Answer value encoding (by question `type`)

The same encoding is used in `responses.json` (`answers` object) — the CSVs flatten it (see below).

| `type` | Value in `responses.json` | Meaning |
|--------|---------------------------|---------|
| `single-choice` | `string` | the exact chosen option text |
| `multiple-choice` | `string[]` | chosen option texts (≤ `maxSelections` when set) |
| `multiple-choice-freetext` | `{ "selected": string[], "freetext": string }` | chosen options + a free-text "other" entry |
| `likert` | integer `1`–`4` | 4-point scale, **no neutral midpoint**. See `scale.minLabel` (=1) and `scale.maxLabel` (=4) in `questions.json` for meaning. Scale direction varies per question — always read the labels. |
| `freetext` | `string` | free text |

> **Important:** Answers are stored as their **full German option text**, not as codes. A question
> ID **absent** from a respondent's `answers` object means it was **not answered** (optional questions
> or an abandoned questionnaire) — absence is *not* the same as an empty string. Because of this, the
> per-question answer count varies (see counts in the data); not every respondent answered every question.

## CSV format notes

- Encoding **UTF-8**, line endings CRLF, fields quoted per RFC 4180 (only when they contain `,` `"` or newlines).
- Columns: `respondent_id, role, class_name, submitted_at`, then one column per question in questionnaire order.
- **`multiple-choice`** values are joined with a pipe `|` (e.g. `ChatGPT|DeepL`). Option texts never contain `|`.
- **`multiple-choice-freetext`** uses two columns: `<id>` (pipe-joined selected options) and `<id>__freetext` (the "other" text).
- **`likert`** is the bare integer `1`–`4`; **`single-choice`/`freetext`** is the raw string.
- An **empty cell** = question not answered.
- Free-text fields are respondents' verbatim input (may contain commas, quotes, or newlines — all CSV-escaped).

## How to join answers to questions

For any answer key (e.g. `S3.4`), look it up in `questions.json` → `questions_by_id["S3.4"]`
to get its `text`, `type`, `options`, and (for Likert) `scale` with `minLabel`/`maxLabel`.
The `S`/`L` prefix already tells you whether it is a student or teacher question.

## Reproducing this export

Generated by reading the DB read-only with `sqlcmd` (`SELECT ... FOR JSON`) and joining the
answers against the question definitions in
`questionaire/app/data/questions.ts` (the application's single source of truth for the codebook).
